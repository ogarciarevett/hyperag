## Runtime limits and retained attempts

All memory rows use the same Llama 3.3-70B answer/judge model and frozen scoring protocol as window 1. Embedding and reranking checkpoint IDs/revisions remain in each metadata file. The TypeScript reference adapter reports version 0.1.0 in the measured metadata; this is not a new installed Rust binary benchmark. Models, prompts, graph rules and scoring were not changed to recover transport failures. Local Postgres reconnects and pause-aware Neo4j deadlines were operational repairs; graph-on dispatch additionally waited for the HTTP listener and a successful Cypher query.

The initial default LoCoMo and DMR attempts failed during machine pauses. The early DMR attempt retained 49 answers. A later default LoCoMo attempt failed before any answers while graph service readiness was incomplete. The lower-priority DMR e5+bgev2m3 attempt was preempted with 114 answers and remained unscored. Full default-template retries completed; failed/partial raw evidence is retained separately under `../results/memory/attempts/`. No selective answer rerun produced a reported score.

Memory latency and wall time are not comparable because of scheduling, pauses and concurrency. NFCorpus reranking reused an already-ingested corpus; its ingestion time is a warm reuse measurement, not a cold build. The NFCorpus/ArguAna rows are retrieval-only; graph is off. The queue used isolated benchmark storage and did not access the first-window result stores.

At queue end the elapsed-time estimate was **USD 23.71 for window 2**, plus **USD 63.60** previously spent, for **USD 87.31 total**. This estimates time through queue end only, not provider-billed final spend or deletion completion. The coordinator received the end message and requested VM deletion. The ledger distinguishes the actual expected-runtime-plus-margin skips from the earlier operator stop-latch messages.
