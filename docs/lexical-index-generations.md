# Private durable lexical generations

Fresh empty generations require an unconsumed full-rebuild source snapshot. Previously consumed readers are refused before creating index files; replay-only input requires the separate validated-base replay path. It has no service caller, worker, active-generation pointer or query scorer. Incremental consumer integration remains a follow-up; the prior generation stays intact during a rebuild.

Create a new directory for each generation; existing paths are refused. On Unix the directory is mode 0700. The index stores IDs, scope, version and recorded/valid times, plus canonical PostgreSQL `simple` lexemes/frequencies as pretokenized postings. Full source text and arbitrary metadata are omitted. Postings still contain private source data. Writer settings are one thread, 32 MiB, manual reader reload and disabled automatic merges; callers must obey the shared resource gate.

Creation and every batch commit record an explicit pending payload containing the target database/epoch/token checkpoint and a schema/tokenizer fingerprint. Each `advance` consumes and commits the next batch; callers cannot skip the owned source stream. An error or cancelled advance permanently prevents publication and requires rebuild. Each batch deletes its IDs before adding final active documents, so absent documents are tombstones and replay is idempotent. A pending generation has no published searcher. `publish` requires its source reader's terminal empty page, writes the complete payload durably, then reloads before returning an immutable searcher. Completed generations refuse further batches.

Recovery acquires the local writer lock while validating metadata and loading the reader. Only a complete generation with the expected format, schema/tokenizer fingerprint and exact current source checkpoint can reopen. Pending, incompatible or mismatched state requires SQL fallback and a fresh rebuild; malformed metadata returns an error with the same fallback requirement. Restoring PostgreSQL to a previous fence cannot make a partial index appear complete. A complete commit interrupted before reader reload can reopen through explicit recovery/reload. Query authorization/time masks and fresh source fencing are still mandatory before enabling retrieval.

The synthetic test reopens real disk commits at partial and complete-before-reload boundaries, checks an older pinned generation, 130 documents across batches, term frequency and stored scope, private permissions, exact checkpoint refusal, incompatible/corrupt payloads and a missing-directory write failure that prevents retry/publication. It simulates interruption at those committed states; it does not perform power-loss testing. Production disk/RSS/write cost, source-to-index worker integration and frozen-question latency/quality remain unmeasured.

`Generation::replay` seeds a fresh directory from a compatible complete base at the replay reader's exact starting checkpoint. It requires an unconsumed replay stream, takes the base writer/metadata locks, and copies regular index files while excluding lock files. Full readers, consumed replays, mismatched checkpoints and pending/incompatible bases are refused. Copied metadata becomes pending at the target fence before any delta is committed; existing owned-stream completion/reload guards still apply.

Base files are copied once, so this path costs O(base disk bytes) plus replay work; reflink optimization and production disk measurements remain future work. An active-generation consumer and atomic CURRENT selection are not enabled here. The replay test keeps unchanged rows, replaces the current version, deletes/invalidates IDs, preserves the old pinned reader/base metadata, and counts live query matches rather than raw term metadata that includes deleted postings.
