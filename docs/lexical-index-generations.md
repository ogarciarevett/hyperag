# Private durable lexical generations

Fresh empty generations require an unconsumed full-rebuild source snapshot. Previously consumed readers are refused before creating index files; replay-only input requires the separate validated-base replay path. It has no service caller, background worker or query scorer. The explicit private consumer below selects completed generations; the prior generation stays intact during a rebuild.

Create a new directory for each generation; existing paths are refused. On Unix the directory is mode 0700. The index stores IDs, scope, version and recorded/valid times, plus canonical PostgreSQL `simple` lexemes/frequencies as pretokenized postings. Full source text and arbitrary metadata are omitted. Postings still contain private source data. Writer settings are one thread, 32 MiB, manual reader reload and disabled automatic merges; callers must obey the shared resource gate.

Creation and every batch commit record an explicit pending payload containing the target database/epoch/token checkpoint and a schema/tokenizer fingerprint. Each `advance` consumes and commits the next batch; callers cannot skip the owned source stream. An error or cancelled advance permanently prevents publication and requires rebuild. Each batch deletes its IDs before adding final active documents, so absent documents are tombstones and replay is idempotent. A pending generation has no published searcher. `publish` requires its source reader's terminal empty page, writes the complete payload durably, then reloads before returning an immutable searcher. Completed generations refuse further batches.

Recovery acquires the local writer lock while validating metadata and loading the reader. Only a complete generation with the expected format, schema/tokenizer fingerprint and exact current source checkpoint can reopen. Pending, incompatible or mismatched state requires SQL fallback and a fresh rebuild; malformed metadata returns an error with the same fallback requirement. Restoring PostgreSQL to a previous fence cannot make a partial index appear complete. A complete commit interrupted before reader reload can reopen through explicit recovery/reload. Query authorization/time masks and fresh source fencing are still mandatory before enabling retrieval.

The synthetic test reopens real disk commits at partial and complete-before-reload boundaries, checks an older pinned generation, 130 documents across batches, term frequency and stored scope, private permissions, exact checkpoint refusal, incompatible/corrupt payloads and a missing-directory write failure that prevents retry/publication. It simulates interruption at those committed states; it does not perform power-loss testing. Production disk/RSS/write cost, source-to-index worker integration and frozen-question latency/quality remain unmeasured.

`Generation::replay` seeds a fresh directory from a compatible complete base at the replay reader's exact starting checkpoint. It requires an unconsumed replay stream, takes the base writer/metadata locks, and copies regular index files while excluding lock files. Full readers, consumed replays, mismatched checkpoints and pending/incompatible bases are refused. Copied metadata becomes pending at the target fence before any delta is committed; existing owned-stream completion/reload guards still apply.

Base files are copied once, so this path costs O(base disk bytes) plus replay work; reflink optimization and production disk measurements remain future work. Atomic selection is handled separately by the consumer below. The replay test keeps unchanged rows, replaces the current version, deletes/invalidates IDs, preserves the old pinned reader/base metadata, and counts live query matches rather than raw term metadata that includes deleted postings.

Replay stays incremental for append-only and marker-only changes. If a replay leaves deleted postings, `advance` discards its copied index and rewinds the source cursor for a full rebuild inside the **same repeatable-read transaction and target fence**. The empty/rebuilding state remains pending and requires another complete source drain before publication. This avoids stale `doc_freq`/`max_doc` and token totals; native compaction also approximates token totals from quantized field lengths, which can change BM25 scores for long documents. Update/delete replay therefore costs a full source scan and reindex in addition to copy/delta work; the synthetic 20,000-document fixture logs fallback wall time and source tuple/index visits. No incremental speed claim is made for that path.

The replay regression compares raw document frequencies for shared, updated and deleted-only terms, live/max document counts, token totals and per-ID BM25 scores with a full rebuild, including an unchanged long document. A source write after opening both comparison snapshots verifies that fallback does not advance to a newer fence.

## Explicit atomic consumer

`Consumer::open(root)` owns a private mode-0700 root with one nonblocking local lock. On Unix, existing roots and generation directories must belong to the effective user with mode0700; CURRENT and the ownership lock must be owned mode0600. Symlinks and other path types are refused before their locks are acquired; recovered index files must be owned regular files without group/world write bits. Unsafe ownership/modes reject opening rather than being silently treated as a rebuild. New-root creation syncs its parent before ownership/publication; a parent-sync failure removes the empty root and returns an error, so retry repeats creation/sync. Existing roots do not repeat that parent sync. Startup follows only a JSON `CURRENT` basename of the form `gen-<32 hex digits>` pointing to a real directory with a compatible complete manifest. Missing, malformed, pending or incompatible pointers leave the reader unavailable until an explicit update; orphan directories are never selected by scanning.

`update(pool)` validates replay lineage from the active checkpoint and copies the complete base into a fresh random directory. A refused stream/base falls back to a full snapshot in another fresh directory. Unchanged fences preserve CURRENT. The consumer owns the generation until source exhaustion, complete commit and manual reload. Copied base files are synced before commit, so activation cannot publish unsynced copied segments.

Activation syncs a mode-0600 temporary pointer in the same root, atomically renames it over CURRENT, syncs the root directory, then swaps the in-memory reader under a short lock. Failure before rename leaves the previous pointer selected. Interruption after rename and before the in-memory swap leaves an old consistent pin; restart follows the complete target on disk. Failed or interrupted builds leave unreferenced generations; no automatic garbage collection or outbox pruning runs.

A cloneable `ReaderHandle` serves old pins while updates build. `at(fresh_source_checkpoint)` returns a searcher only for the exact database/epoch/token fence; a missing or lagging reader requires SQL fallback. The caller still must obtain fresh authorization and source state and apply scope/time masks before retrieval. This module has no service caller or background loop.

The synthetic consumer test covers multi-batch replay with unchanged rows, updates/tombstones, marker-only epochs, retention gaps, missing epochs, resets, divergent tokens, one root owner, no-op updates, pending/complete orphan windows, a pre-rename write failure, restart after rename and unsafe CURRENT paths/symlinks. These are committed-state simulations, not power-loss tests. Production copy/disk/RSS cost and frozen-question latency/quality remain unmeasured.

## Bounded consumer steps

`step(pool)` advances one64-document source page and returns whether more work remains; `update(pool)` retains its explicit full-update behavior by looping over steps. Pending state is taken before awaiting work, so cancellation or failure drops its source transaction and never replaces CURRENT or the prior reader. Replay copies yield between256KiB chunks and write incomplete metadata before yielding; canceling a copy cannot leave a recoverable complete generation.

The root selector defaults to a database-UUID namespace under the canonical, user-owned HOME directory (`.hyperag-tantivy-<uuid>`), never the working directory. The consumer still validates every resolved ancestor and refuses unsafe owners/modes/types with the offending path. Existing roots are never chmod-ed to bypass those checks.
