# Private lexical source reader

The Rust source reader prepares a consistent rebuild or replay for a future index worker. It is private and has no service caller. It starts no worker, changes no retrieval setting and writes no source data or index files.

`SourceSnapshot::open(pool, None)` starts a full rebuild. Passing a completed checkpoint instead requests replay: database identity, retention floor, epoch range, every epoch's predecessor/successor tokens and the final fence must agree. A missing epoch, reset marker or mismatched lineage returns an error requiring SQL fallback and rebuild. Authorization-only epochs advance the checkpoint without manufacturing document changes. The retention floor itself is replayable; checkpoints below it are refused.

The read-only repeatable-read transaction holds the fence, events and final rows in one snapshot without taking the advisory writer lock. Each batch contains at most 64 distinct IDs, coalesced across transactions, and their final active documents. Documents carry current version, scope, recorded/valid times and canonical PostgreSQL `simple` lexemes with frequencies. Deleted, missing and inactive documents have IDs without document payloads: a future worker must delete every batch ID before adding its active documents. Full source text and arbitrary metadata are omitted; lexemes remain private source data.

Only an empty terminal page exposes `completed_checkpoint()`. Consuming a page never completes an epoch, including epochs larger than 64 IDs. This means source exhaustion only: the future worker must still commit/reload the index before publishing, use an explicit pending payload for partial disk commits, and fence every query against fresh PostgreSQL authorization/state. Source writers can advance while this snapshot is held. Drop the reader to release its transaction; long snapshots retain PostgreSQL MVCC history.

The synthetic Rust contract test covers 130-ID paging with concurrent writers, final-row replay/tombstones, metadata/term frequencies, marker-only epochs and rebuild after lineage, gap, retention or reset failures. Disk recovery, the index consumer, native block-WAND/scoped masking and frozen-question latency/quality remain subsequent slices. No live migration or cost measurement is included.
